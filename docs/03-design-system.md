# Design System

## Direction

Trustworthy, calm, modern, useful to non-technical owners. Avoid generic purple AI dashboards, excessive gradients, glowing robots, fake statistics, and dense enterprise UI.

## Principles

- Status and next action over decoration.
- Plain Brazilian Portuguese.
- Provider jargon only in advanced diagnostics.
- Actionable warnings.
- Honest usage.
- Progressive disclosure.
- Mobile-first critical flows.
- Keyboard and screen-reader support.

## Tokens

Centralize brand and neutral colors, semantic statuses, typography, spacing, radii, shadows, focus rings, motion, containers, breakpoints, and z-index.

## Navigation

Desktop:
- Overview
- Channels
- Assistant
- Knowledge
- Leads
- Appointments
- Analytics
- Team
- Billing
- Settings

Top bar:
- tenant switcher;
- health;
- help;
- notifications;
- user menu.

Mobile uses a drawer and persistent urgent health indicator.

## Components

Button, IconButton, inputs, Select, Combobox, Checkbox, RadioGroup, Switch, Dialog, Drawer, Dropdown, Tabs, Tooltip, Toast, Alert, StatusBadge, Card, DataList, ResponsiveTable, Pagination, Skeleton, EmptyState, ErrorState, Stepper, UsageMeter, PricingCard, ChannelCard, SourceCitation, HandoffStatus, and AuditTimeline.

Each relevant component supports loading, disabled, error, empty, permission-restricted, and mobile states.

## Dashboard questions

- Are channels healthy?
- Is AI active?
- Are customers waiting for humans?
- What usage remains?
- What leads and appointments were produced?
- What must the owner do next?

## Content

Use direct, calm language. Explain destructive consequences. Never guarantee AI outcomes. Distinguish requests from confirmed appointments.
